# 按公司类型定制简历

## 第一原则

**同一批事实，换排列、换措辞、换取舍——不换事实。**

一份简历改 5 个版本，改的应该是：

1. **顺序**：哪段经历放第一（HR 平均看 15 秒，第一屏决定生死）
2. **详略**：同一段经历，A 版展开成 3 条 bullet，B 版压成 1 行
3. **措辞**：同一件事，对券商叫"变量控制与误差处理"，对内容公司叫"选题验证与效果归因"
4. **选课/选分**：只露与该类型相关的高分课程，不必全列
5. **技能栏**：只写该类 JD 真会看的技能

绝对不能做的：补一段没做过的实习、编一个没用过的工具、把"了解"写成"精通"、给没量化过的结果编数字。

## 六类公司的画像

### 1. 互联网大厂（字节、腾讯、百度、快手、OPPO、小红书、Shopee、eBay、美团）

| 维度 | 内容 |
| --- | --- |
| 真正在看 | 数据能力（SQL/Python）→ 业务理解 → 跨团队推进 → 能不能连续干 6 个月 |
| 第一屏放什么 | 与岗位同名的项目/经历，其次才是教育背景 |
| 结构顺序 | 定位句 → 相关经历 → 技能 → 教育 → 其他 |
| 措辞 | 动词开头、数字结尾，一条一行；不写形容词 |
| 加分 | 科研/竞赛里的"数据→结论→动作"闭环；AIGC 实操（现在很吃） |
| 减分 | 学生会/社团的层级叙事；与岗位无关的课程罗列 |
| 自检 | 每条经历能否回答"所以业务上发生了什么变化" |

### 2. 金融券商（中金、中信、第一创业、众安、各类基金/银行）

| 维度 | 内容 |
| --- | --- |
| 真正在看 | 数理统计功底、Python 建模、报告撰写、严谨度、能不能过学历筛 |
| 第一屏放什么 | 教育背景 + 数理课程分数（这行就是看这个） |
| 结构顺序 | 教育（含核心课程分数）→ 数理/建模经历 → 技能 → 其他 |
| 措辞 | 克制精确，"参与/协助/负责"严格区分贡献度；不夸大 |
| 加分 | 概率论、数理统计、随机过程、计量经济学的高分；能读英文研报 |
| 减分 | 无法自证的收益承诺（"提升收益 X%"）；花哨排版 |
| 自检 | 有没有出现无法在面试中自圆其说的量化 |

### 3. 生物医药 / 科研院所（微基因、华大、药明、CRO）

| 维度 | 内容 |
| --- | --- |
| 真正在看 | 专业对口度、实验技能完整性、英文文献、科研项目参与深度 |
| 第一屏放什么 | 科研项目（写清完整链路和你的具体分工） |
| 结构顺序 | 科研经历 → 专业技能 → 教育（含实验课分数）→ 其他 |
| 措辞 | 学术化，名词必须准确（菌株、培养基、无菌操作、表型、引物） |
| 加分 | 从选题到数据到结论的完整闭环；能独立检索并翻译英文文献 |
| 减分 | 把 AI 绘图当主线；专业名词写错一个直接出局 |
| 自检 | 面试官追问实验细节时，每一步你都能答上来吗 |

### 4. 外企 / 跨国公司（ZURU、eBay、Shopee、联合利华、宝洁）

| 维度 | 内容 |
| --- | --- |
| 真正在看 | 英文读写、结构化分析、商业表达、跨文化协作 |
| 第一屏放什么 | 英文定位句 + 最相关的一段经历 |
| 结构顺序 | Summary → Experience → Skills → Education |
| 措辞 | Action verb + metric；短句；不堆形容词；避免中式长句 |
| 加分 | 语言成绩分项（阅读分尤其）、英文材料处理经历 |
| 减分 | 中式荣誉直译（"积极分子"→ selected as outstanding member，不要逐字翻） |
| 自检 | 英文版能不能被 native 一眼看懂，时态/拼写有没有错 |

### 5. 消费零售 / 快消（百丽、宝洁、名创、安踏）

| 维度 | 内容 |
| --- | --- |
| 真正在看 | 调研方法（问卷/访谈/桌面研究）、行业洞察、结论呈现、执行力 |
| 第一屏放什么 | 一段能证明"你会做研究并得出结论"的经历 |
| 结构顺序 | 定位句 → 研究/分析经历 → 技能 → 教育（露双一流） |
| 措辞 | 结论先行：先给判断，再给依据 |
| 加分 | 自己独立得出的洞察结论；跨部门推动落地的证据 |
| 减分 | 纯技术细节（窗口函数这种一句带过） |
| 自检 | 有没有一个"属于你自己的判断"，而不是资料汇编 |

### 6. 创业公司 / AI 初创（飞未云科这类数据标注、AI 应用公司）

| 维度 | 内容 |
| --- | --- |
| 真正在看 | 上手速度、AI 工具实操、一人多岗、细心耐性、自驱 |
| 第一屏放什么 | 最能证明"没人教也能自己搞出来"的那件事 |
| 结构顺序 | 定位句 → 实操项目 → 技能清单 → 教育 |
| 措辞 | 直接具体，少用"负责/参与"，多用"我做了 X，结果 Y" |
| 加分 | 自建工作流、自动化脚本、从 0 起号这类"野生能力" |
| 减分 | 大公司式的流程语言；空谈方法论 |
| 自检 | 有没有一件"你主动做的、没人要求你做的事" |

## 改写公式

一条 bullet 的骨架：

> **动作 + 对象 + 方法/工具 + 结果（可验证）**

不合格：`负责社团活动的策划与组织`
合格：`统筹 6 场校级活动（端午/国庆），协调 12 名干事与 3 个部门，活动到场率较上学期提升【待填】`

不合格：`熟练使用 AI 工具`
合格：`用 ComfyUI 搭建出图工作流，3 周产出 40 张超古代壁画复原图，被遗迹调查报告收录`

**没有数字时不要编**，改用可验证的事实（次数、人数、周期、规模、排名），或留 `【待填：xxx】` 让本人补。

## 缺口怎么处理

三类缺口，三种写法：

| 缺口类型 | 处理 |
| --- | --- |
| 完全没接触过（如 SQL） | **不写**。写了面试第一个问题就露馅。改为在投递留言里说"正在补"，或用两周做个小项目补上再写 |
| 接触过但没项目（如 Excel） | 写进"技能"但标注水平（"数据透视表/VLOOKUP，课程作业使用"），不要写成"精通" |
| 有经历但没量化 | 补量化，或改用规模/周期描述 |

`tailor.mjs` 输出的「跨类型共性缺口」表就是这个逻辑：出现在越多 JD 里的缺口，越值得花两周补一个真项目。

## 输出规范

- 一个类型一版，文件名：`简历_<类型>_<方向>.md`
- 每版控制在一页（A4，10.5pt，行距 1.15）
- 版本之间**只改内容和顺序，不改视觉模板**——视觉统一，HR 才看不出你在海投
- 每版顶部保留一行"投递记录"注释，标明这版投过哪些公司，避免同一家公司收到两个版本

## 定稿前自检（逐条打勾）

1. 第一屏出现的内容，是不是这个岗位最想看的？
2. 每条 bullet 有没有动词和结果？
3. 有没有出现简历原文里没有的技能/数字/经历？
4. 专业名词、公司名、岗位名有没有写错？
5. 时间线有没有断档或重叠？
6. 一页装得下吗？装不下先删与岗位无关的，不要缩字号。
